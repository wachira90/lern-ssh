### Steps:

#### 1. **Generate ED25519 SSH Key Pair (if you don't already have one)**

On the client machine, generate an ED25519 SSH key if you don’t already have it:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519
```

This command will generate a key pair (`id_ed25519` and `id_ed25519.pub`). Ensure you securely store your private key.

#### 2. **Configure GitLab to Accept ED25519 Keys**

GitLab uses the same SSH configuration as the system’s SSH server. By default, GitLab is set up to use SSH for cloning repositories. You can enforce using ED25519 key authentication by configuring the SSH daemon (`sshd`) on your server.

#### 3. **Configure the SSH Daemon for ED25519 Only**

You need to edit the SSH configuration file (`/etc/ssh/sshd_config`) to disable other key types (like RSA, DSA, etc.) and allow only ED25519.

1. Open the SSH configuration file for editing:

   ```bash
   sudo nano /etc/ssh/sshd_config
   ```

2. Look for the `PubkeyAcceptedKeyTypes` and `HostkeyAlgorithms` directives. If they are not present, you can add them.

   Add the following lines to the file to explicitly allow only ED25519 keys:

   ```bash
   PubkeyAcceptedKeyTypes +ssh-ed25519
   HostkeyAlgorithms +ssh-ed25519
   ```

3. Disable other key types (like RSA or DSA) by adding the following lines to block them:

   ```bash
   # Disable RSA, DSA, and other key types
   PubkeyAcceptedKeyTypes -ssh-rsa -ssh-dss
   ```

4. Save the file and exit the editor (press `CTRL+X`, then `Y`, and hit `Enter` to confirm).

#### 4. **Restart the SSH Service**

After modifying the SSH configuration, restart the SSH service to apply the changes:

```bash
sudo systemctl restart ssh
```

#### 5. **Add the Public Key to GitLab**

Next, you need to add your public key (`id_ed25519.pub`) to GitLab so it can authenticate you when connecting.

1. Log in to GitLab using your web browser.
2. Go to **Profile settings** (click on your avatar in the upper right corner).
3. Go to **SSH Keys** under the **Access Tokens** section.
4. Paste the content of your `id_ed25519.pub` file into the SSH key field and give it a title.
5. Save the SSH key.

#### 6. **Test the SSH Connection to GitLab**

To verify that everything is set up properly, try connecting to GitLab via SSH:

```bash
ssh -T git@gitlab.com
```

This should log you in using your ED25519 key without asking for a password. If you have any other SSH keys set up in your agent, you can specify the ED25519 key using the `-i` option:

```bash
ssh -i ~/.ssh/id_ed25519 -T git@gitlab.com
```

#### 7. **Verify SSH Configuration**

You can check the SSH server's key exchange algorithms and ensure only `ssh-ed25519` is available by running:

```bash
ssh -vT git@gitlab.com
```

The output should indicate that only ED25519 key exchange is happening. If other key types are being used, the configuration may not be correct.

### Additional Notes:

* Ensure that your private key file (`id_ed25519`) is protected with correct permissions:

  ```bash
  chmod 600 ~/.ssh/id_ed25519
  ```
* If you are using any other SSH configurations or proxy settings, make sure they are not overriding these key restrictions.

By following these steps, you will configure both GitLab and the SSH server on Ubuntu 22.04 to accept connections only using the ED25519 key authentication type.

To configure SSH on an Ubuntu system to force the use of ED25519 key type for login, you can follow these steps:

1. Edit the SSH server configuration file:

```
sudo nano /etc/ssh/sshd_config
```

2. Add or modify the following lines:

```
HostKeyAlgorithms ssh-ed25519
PubkeyAcceptedKeyTypes ssh-ed25519
```

3. Save the file and exit the editor.

4. Restart the SSH service:

```
sudo systemctl restart sshd
```

5. Generate an ED25519 key pair on the client machine if you haven't already:

```
ssh-keygen -t ed25519 -C "your_email@example.com"
```

6. Copy the public key to the server:

```
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@server
```

7. Test the connection:

```
ssh user@server
```

This configuration will force the server to only accept ED25519 keys for public key authentication. Make sure you have a valid ED25519 key pair before applying these changes, or you might lock yourself out of the server.
